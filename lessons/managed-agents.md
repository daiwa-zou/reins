## Learnings
- Harnesses encode assumptions about what Claude cannot do alone, and those assumptions go stale as models improve. An earlier harness used context resets to counter "context anxiety" (Claude Sonnet 4.5 wrapped up tasks early as it sensed the context limit approaching); on Opus 4.5 the behavior was gone and the resets were dead weight.
- Managed Agents is a hosted service for long-horizon agents built around a small set of stable interfaces meant to outlive any implementation, borrowing from operating systems (process and file abstractions outlived the hardware). It has three virtualized components that can each be swapped without disturbing the others: the session (append-only log of everything that happened), the harness (the loop that calls Claude and routes tool calls to infrastructure), and the sandbox (the environment where Claude runs code and edits files).
- "Don't adopt a pet": the first design put session, harness, and sandbox in one container (direct file-edit syscalls, no service boundaries). A failed container lost the session, unresponsive containers had to be nursed back, and engineers would have had to shell into containers holding user data, which blocked debugging.
- Debugging via the WebSocket event stream could not localize failures (a harness bug, a dropped packet, and an offline container looked identical), and the harness assumed resources were colocated, so customer VPCs needed network peering or running the harness inside the customer environment.
- Decouple brain from hands: the brain is Claude plus harness, the hands are sandboxes and tools, and the session is the event log. Each is an interface with minimal assumptions about the others.
- The container becomes cattle: the harness calls every hand through one tool-style interface, `execute(name, input) -> string`. A dead container surfaces as a tool-call error Claude can handle, e.g. retrying on a fresh container via `provision({resources})`.
- The harness becomes cattle too: the session log lives outside the harness, so a crashed harness is replaced. `wake(sessionId)` starts a new one, `getSession(id)` returns the event log, execution resumes from the last event, and progress is recorded with `emitEvent(id, event)`.
- Security boundary: in the coupled design credentials sat in the same container as untrusted Claude-generated code, so a prompt injection could expose them. The fix is that tokens are never reachable from the sandbox, and relying on narrow token scoping encodes assumptions about what Claude cannot do, a weak bet as capability grows.
- Credential handling: bundled or vaulted auth keeps credentials with a resource or in a vault outside the sandbox; for git, the repo token is used at sandbox init to clone and wire the remote so push/pull work without the agent handling it; for MCP tools, OAuth tokens live in a vault and Claude calls MCP through a dedicated proxy that takes a session-associated token, fetches credentials, and calls the external service, so the harness never sees credentials.
- The session is not Claude's context window. Common fixes for long tasks are irreversible (compaction, the memory tool writing to files, context trimming of old tool results or thinking blocks), and irreversible discards are risky because later turns may need what was removed; compacted messages are recoverable only if stored elsewhere.
- The session is a durable context object outside the window, stored in the event log rather than the sandbox or a REPL. `getEvents()` reads positional slices so the agent can resume where reading stopped, rewind to see what led to an event, or reread context before an action.
- The harness may transform fetched events before they enter the window (for prompt-cache hit rate or other context engineering). Durable storage (session) is deliberately separated from context management (harness) because future context-engineering needs cannot be predicted; the session only guarantees durability and queryability.
- Many brains: decoupling removed the VPC-peering requirement and improved latency. Previously every session paid full container setup (clone repo, boot process, fetch pending events) before inference; now containers are provisioned only when a tool call needs one and inference starts as soon as the orchestration layer pulls pending events. p50 time-to-first-token dropped about 60% and p95 dropped over 90%, and scaling brains means starting more stateless harnesses and attaching hands on demand.
- Many hands: Claude must now choose among many execution environments, "a harder cognitive task than operating in a single shell." The single container had been a bottleneck, since its failure lost state for every hand. Because every hand has the same name-and-input interface, the harness does not care whether a hand is a container, a phone, or a Pokemon emulator, and brains can pass hands to each other.
- Conclusion: Managed Agents is a "meta-harness," opinionated about the interfaces around Claude (state via session, computation via sandbox, scaling to many brains and hands) but unopinionated about the specific harness, and intended to host Claude Code, task-specific harnesses, and future designs.

## Harness implications
- Separate three concerns with hard interfaces: session (durable event log), harness (stateless loop), and sandbox/tools (hands). Each should be independently replaceable and restartable.
- Make the session log the source of truth, not the context window; compaction and trimming operate on a view derived from the log, and the full history stays queryable (resume, rewind, reread).
- Expose a single uniform tool interface (`execute(name, input) -> string`) for all execution environments so new hands (containers, devices, emulators, browsers) plug in without harness changes.
- Treat infrastructure failures as tool errors the agent can handle (retry, reprovision) rather than fatal harness crashes; the UI should show provisioning state per hand. Support crash recovery by replay with `wake(sessionId)` semantics where any harness instance can pick up a session from its last event.
- Keep credentials out of the sandbox: vault plus proxy for MCP/OAuth, pre-wired git remotes, bundled resource auth. Never depend on token scoping alone.
- Provision lazily: start inference immediately and attach sandboxes only on first tool call to cut TTFT.
- Build failure-localizing observability that distinguishes harness bugs, transport drops, and dead sandboxes in the event stream and UI, and make debugging possible without shelling into user-data containers.
- Design harness features as removable assumptions (e.g. context resets) that can be retired when a new model no longer needs them, and keep them configurable per model. In the UI, show which hand each action ran on and let the user inspect or hand hands between agents.
