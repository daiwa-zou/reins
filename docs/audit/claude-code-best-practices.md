## Gaps
- No user-triggered reset or side channel: add a "Reset builder with handoff" button (emits `context.reset` and drops `builderHistory`) and a "Ask without recording" box that routes a question to a scout instead of the builder.
- No preservation rules: add `context.preserve` to `RunConfig`, included in the compaction request and the handoff note.
- No per-turn goal check or stop hook: add an optional `verifyCommand` to `RunConfig` run by the harness after each builder turn (deterministic), blocking `finish` until it exits 0, with a cap of N consecutive blocks before pausing for the human.
- Plan is not editable: render the spec in the `afterPlan` ApprovalCard as a textarea and write the edited text back to `.reins/spec.md` on approve.
- No hooks or CLAUDE.md lint: support `.reins/hooks.json` with `afterEdit` and `beforeFinish` shell commands run by the orchestrator, and emit a warn note when CLAUDE.md exceeds 6000 characters instead of truncating silently.
- No allow patterns: add `allowPatterns` to `GuardrailPolicy` (narrow, e.g. `^npm run lint`) honoured before the `ASK` rules.
- No checkpoints: snapshot files touched by `write_file`/`edit_file` under `~/.reins/runs/<id>/checkpoints/<seq>/` and add "Restore workspace to here" in the Transcript scrubber.
- No resume of interrupted runs: persist `builderHistory` (direct) or `builderSession` (SDK) to the run dir after each phase and offer "Resume" on runs marked interrupted.
- No headless mode or parallel fan-out: add `reins run --task ... --workspace ... --json` that drives the same `RunManager` and streams events as JSONL, and allow parallel repeats when each run gets its own `git worktree`.
- No MCP or piping: see MCP gap in advanced-tool-use; add `--stdin` to the CLI to attach piped text to the task.
- Fix rounds keep the polluted history: after a failed round, start the builder from a fresh conversation with the evaluation summary as the handoff (reuse `shouldResetBuilder`) when `maxFixRounds` is reached once.
- Tests are editable by the builder: in the contract stage, record the test files named in `verify` commands and have the evaluator fail a round when `git diff` shows them modified.
- No interview step: add an optional "Interview me" pre-phase that uses `approval.requested` prompts to ask 3-5 questions and writes the answers into the spec.
