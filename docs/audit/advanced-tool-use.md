## Gaps
- No MCP toolsets: add an `mcpServers` entry to `RunConfig` and, in the direct engine, fetch each server's tool list and register it in `ALL_TOOLS` with `deferred: true` by default and a per-tool `alwaysLoad` override.
- Deferred set and token cost are invisible: in the Inspector list all tools with a loaded/deferred badge and `estimateTokens(JSON.stringify(schema))` next to each.
- No programmatic tool calling: add a `run_code` tool that executes a short script in the sandbox with Reins tools exposed as functions (via a local HTTP shim) and returns only stdout, flagging it in the Stage as a collapsible group of inner calls.
- No idempotency metadata or return-format docs: add `idempotent: boolean` and a `returns` description to `ToolDef` and refuse non-idempotent tools inside `run_code` without approval.
- Nested tools lack examples: add one `input_examples` entry each to `update_progress`, `review_contract` and `report_evaluation`, and a `registry.test.ts` case that fails when a tool with an array-of-object parameter has no example.
- No tool-token alert: emit a warn `note` from `snapshot()` when the estimated tool-schema slice exceeds 10K tokens and suggest deferring.
- No bottleneck telemetry: derive per-tool call count, error count and total result tokens in `derive.ts` and show them in the Guardrails or Context tab.
- Truncation instead of selective return: let `bash` accept an optional `summary_only` flag that returns exit code plus the last 20 lines, and record the full output to `.reins/logs/` for the UI.
