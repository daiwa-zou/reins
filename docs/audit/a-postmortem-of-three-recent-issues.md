## Gaps
- No canary check on model output: add a `text`/`tool.result` post-processor that flags non-target-script characters and unparsable code written by `write_file`/`edit_file` (a `tsc`/`node --check`/`python -m py_compile` probe by extension) and emits a warn `note`.
- Quality signals are not sliced: let `groupTrials` optionally key by `model`, `engine` and `harnessVersion` (fields already on `Trial`) and add a "segment by" selector to the Reliability tab.
- No report-to-change correlation: add a one-click "Report this run" that writes `~/.reins/reports/<runId>.json` with the config, harness version and a pointer to the event log, and list reports by harness version next to trial sets.
- Request/user-level stickiness is not represented: at minimum show, per trial set, how many consecutive failures occurred (a sticky-failure streak) rather than only the pass rate.
- Evaluation is outcome-only: add transcript-level checks to the evaluator's report (count of tool errors, denied actions, truncated outputs, non-ASCII bursts in model text) as soft criteria.
- Workarounds in `recover()` are untracked: give each flag a comment with the API error it masks and a test in `loop.test.ts` that fails without the workaround (there is one such test today, at `loop.test.ts:145`).
- No redacted export: add `GET /api/runs/:id/export` that writes the JSONL with tool outputs scrubbed by the same patterns as `scrubbedEnv`.
- No cross-engine equivalence test: run the orchestrator end-to-end test once per engine with the same scripted inputs and assert the event sequence matches, and add a CI workflow that runs `npm test`.
- No feedback path: a `/bug`-style action in the TopBar that captures the selected run's config and last N events into a report file.
- Beta flags active per request are not in the trace: include `betas` and `context_management` edit types in `turn.finished` so a rejected or absent beta is joinable to a quality change.
