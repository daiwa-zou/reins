## Gaps
- No egress proxy or domain allowlist: add `allowedDomains` to `GuardrailPolicy`, pass it to the SDK sandbox in `claudeCodeLoop.ts:215` (today the `network` block is dropped entirely when network is on), and for the direct engine run a local HTTP(S) proxy outside the sandbox with `HTTP_PROXY`/`HTTPS_PROXY` set in `runShell`'s env, raising an `approval.requested` on the first contact with a new domain.
- Sandbox violations are invisible: when `runShell` output under the sandbox matches "operation not permitted", emit a `guardrail.decision` (or a new `sandbox.violation` event) naming the path or host, render it on the Stage with its own badge, and offer "allow this path for the run".
- Reads of secrets are open: add `(deny file-read* (subpath "~/.ssh") (subpath "~/.aws") (literal "~/.git-credentials") (subpath "~/.config/gh"))` to `seatbeltProfile`, keeping reads of the rest of the disk open for builds.
- `confinePath` (`policy.ts:120-127`) should `realpathSync` the deepest existing ancestor of the target and re-check it against the workspace, so a symlink inside the workspace cannot write outside it.
- The API key re-enters the SDK subprocess environment (`claudeCodeLoop.ts:184`): use the SDK's `CLAUDE_CONFIG_DIR` login only and drop `ANTHROPIC_API_KEY` from the env unless no login exists, or document that on the Claude Code engine the agent's shell can read it.
- Linux has no sandbox: add a bubblewrap backend to `sandboxArgs` (`bwrap --ro-bind / / --bind <ws> <ws> --unshare-net`) and show `sandboxAvailable` as a badge in New run and Guardrails so a user on Linux knows the switch is inert.
- Prompt-reduction is unmeasured across runs: add "asked you per 100 tool calls" to `Trial` and the Reliability table so a policy change can be compared between trial sets.
