## Gaps
- Level 3 files are unreachable for bundled/user skills: let `read_skill` accept an optional `file` argument that reads a named sibling file from the skill's own directory (path-confined to `s.dir`).
- Skill index cost is invisible: compute `estimateTokens(skillsPromptSection(...))` in `projectContext` and emit it in the Environment note and the Context tab.
- No name/description lint: in `loadSkills` warn (via a `note` event at run start) when `description` is empty, over 200 characters, or duplicates another skill's.
- No runnable-script convention: parse an optional `scripts:` frontmatter list and expose each as a deferred tool that runs `bash <skill-dir>/<script>` under the sandbox, so "run this" is explicit and shows as a tool call.
- No authoring loop: after `wrapup`, when the evaluation failed at least once, prompt the builder (or offer the user a button) to write `.reins/skills/<slug>/SKILL.md` capturing what went wrong and what fixed it.
- No trust gating: show installed skills with `source` and file list in the Harness tab, and require a one-time approval (`approval.requested` kind `skill`) before a workspace or user skill is indexed for a run.
- No installed-skills view or files-loaded trace: add a "Skills" section to the Inspector listing installed skills, highlighting the ones read this run (from `tool.called name=read_skill`).
- No version field: parse `version:` from frontmatter and include it in the Environment note so a skill change is joinable to a quality change.
