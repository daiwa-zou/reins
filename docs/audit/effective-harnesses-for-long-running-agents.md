## Gaps
- Titles of existing features are editable: in `mergeFeatures`, keep the stored `title` for a known id and only accept `status` and `note` changes, emitting a warn note when the agent tried to rename or drop one.
- No `init.sh`: have the planner write `.reins/init.sh` (how to install, run and smoke-test), run it in `Orchestrator.run` before each build phase with a timeout, and log its output as a `note`; the builder's preamble then starts from a known-good state.
- One build phase does all features: add `buildMode: "one-feature-per-session"` that ends the build loop after each feature flips to done (fresh conversation, commit, progress note) and loops until the list is done or the budget is spent.
- `finish` accepts a dirty tree: when `gitCommits` is on, run `git status --porcelain` in the `finish` handler and return the dirty list instead of finishing.
- No browser verification: add a deferred `screenshot(url)` / `browse(url, steps)` tool (Playwright) for the builder and evaluator when a contract names a URL, and let the `verify-like-a-user` skill say what it cannot see (native dialogs, downloads).
- Startup routine is advisory: inject the last 40 lines of `progress.md` and `git log --oneline -20` into the build phase's first message (`projectContext()`), so the routine does not depend on the model remembering to read them.
