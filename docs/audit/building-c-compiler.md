## Gaps
- No run-forever mode: add a `loopUntilDone` option that, after wrapup, starts a new run on the same config while `features.json` has non-done items and budget remains, with each iteration's starting sha in its Environment note.
- No git coordination: out of scope for one builder, but to allow N parallel runs add a `.reins/locks/<feature-id>` claim written by `update_progress` when a feature goes `in_progress`, refused if the file exists.
- No regression gate on commits: run the contract's hard `verify` commands before `commit()` and skip the commit (with a warn note) when one fails.
- No fast-sample tests: add a `verify_sample` helper that runs a deterministic 10% subset of test files (seeded by run id) and tell the builder to use it between features and the full suite before `finish`.
- Full output is lost: write untruncated tool output to `~/.reins/runs/<id>/tool-output/<toolUseId>.txt` and link it from the CallRow when `truncated` is true.
- The model is time-blind: include elapsed minutes and remaining USD in the operator note delivered before each turn (`deliverSteer`) or in the phase's first message.
- No shards or bisection: when a hard criterion fails for the same reason on two consecutive rounds, have the orchestrator ask a scout for a bisection plan and feed it to the fix round.
- `pkill` is allowed and the server is in the agent's process tree: add `/\bpkill\b/` to `DENY`, and spawn shell commands under `setsid`/a separate process group so a stray kill cannot reach the server.
- A green evaluation finishes the run unattended: default `pauses.afterEvaluation` to true, or add a "Mark as shipped" button distinct from the pass badge.
- Failures do not become tests: on a failed round, append the failing criterion to `.reins/regressions.json` and have the contract evaluator pull those in as hard criteria on the next run of the same task.
