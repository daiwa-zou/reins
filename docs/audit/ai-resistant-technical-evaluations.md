# Building AI-resistant technical evaluations
Source: https://www.anthropic.com/engineering/AI-resistant-technical-evaluations
Lesson file checked against the original: yes (added one Learnings bullet: with unlimited time humans still beat the models, so time-limited and open-ended results must be reported separately)

## Gaps
- No per-version comparison: add a "by harness version" (and "by model") breakdown inside each trial set, reusing `trialRates` on the subset.
- No score-vs-budget view: plot each trial's `costUsd` (x) against outcome and `fixRounds` (y) in the Reliability tab; a scatter is enough.
- Steering is not separated in results: count `steer.delivered` events in `trialFromEvents` and show steered trials with a marker; offer "unsteered only" rates.
- Tool-building is not recorded: when `write_file` targets a path that is later the argument of a `bash` call in the same phase, emit a `note` "built and ran a helper script" so the Transcript can filter on it.
- No private task library: add `~/.reins/tasks/*.md` with frontmatter `created` and `public: false`, selectable in the New run dialog, and show task age on the trial set.
- No numeric metric: allow a contract criterion to carry an optional `metric` command whose numeric stdout is recorded per evaluation round and trended in the Contract tab.
- No action timeline: render `tool.called` events on a time axis per role (one lane each) in the Transcript header so a stall or a loop is visible at a glance.
- No task taxonomy: add optional `tags` to `RunConfig` and group trial sets by tag.
- A finished run cannot be extended: add "Continue with +$N budget" that starts a new run with `resume` of the builder session (claude-code engine) or the saved `builderHistory` (direct engine).
