## Gaps
- Compaction is not tunable: add `context.preserve: string` (free text) to `RunConfig`, pass it as the compaction instruction when the API accepts one, and include it in the reset handoff; show the compaction summary in an editable textarea on the Context tab when the run is paused.
- Reset threshold uses a string-length estimate: keep the last measured `promptTokens` per role from `context.snapshot` and compare that in `shouldResetBuilder` (`orchestrator.ts:289`).
- The SDK engine's composition is fabricated (`claudeCodeLoop.ts:278`): either omit `composition` (make it optional) and show only the measured total, or estimate from the recorded tool results like the direct engine does.
- No per-call context cost: add `estimateTokens(output)` to `tool.result` and show it on the CallRow so a 20k-token `cat` is visible as such.
- Tool overlap is unlinted: add a registry test that fails when two tool descriptions share more than N content words or two tools accept the same parameter under different names (`path` vs `file`).
- No strategy selection: in `checkRunConfig`, warn when compaction, reset and scouts are all on for a short task (budget < $3 or Minimal), and add a one-line "context strategy" readout to the Context tab naming which of the three is active.
