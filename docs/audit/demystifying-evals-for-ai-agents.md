## Gaps
- Trials are not isolated: give `repeat()` a `fresh: true` option that runs each trial in `git worktree add` of the base commit with an empty `.reins/`, and label trial sets as "shared workspace" vs "fresh" so the two are not mixed.
- No deterministic grading: when a criterion's `verify` is a shell command, have the orchestrator run it itself after `report_evaluation` and record `observedExit`/`observedOutput` next to the evaluator's `pass`; disagreement becomes a visible "grader vs harness" row.
- No "unknown" or "grader wrong": extend `CriterionResult` with `outcome: "pass" | "fail" | "unknown"` and `disputed?: string`, let the evaluator mark unknown, and let the user flag a result on the Contract tab (stored as a `note` event) so the Reliability set can show disputed trials.
- No broken-task signal: in `groupTrials`, when `n ≥ 3` and `passes === 0`, add `flag: "probably-broken"` and render "0 of n passed: check the task and criteria before blaming the agent" on the Reliability card.
- No suites or graduation: add `$REINS_HOME/suites/<name>.json` (task, workspace, expected pass rate) with a "Run suite" action and a `regression` badge once a set's pass rate stays above a threshold for N trials.
- No task bank from failures: add "Save as eval task" on a failed run's EndCard that writes the task, workspace and contract to a suite file.
- Trial metrics are thin: add `turns`, `toolCalls` and `firstTurnMs` to `trialFromEvents` and the Reliability table.
